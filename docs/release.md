# Підготовка до випуску на iOS

Версія 1.2.0 має синю іконку 1024 × 1024, світлу, темну та системну теми, ідентифікатор `com.sh1kami.osobystirechi`, українські пояснення доступу до камери й фото та профіль `production` у `eas.json`.

## Перевірка збірки

1. Виконайте команди з README і сценарії M01–M17 в Expo Go. Використовуйте окремі тестові дані для відновлення копії.
2. Увійдіть в Expo та перевірте володіння ідентифікатором застосунку в Apple Developer. Якщо EAS ще не пов’язаний із проєктом, налаштуйте зв’язок під власним обліковим записом.
3. Виконайте `npx eas-cli@latest build --platform ios --profile production`. Для збірки магазину потрібні підпис і обліковий запис Apple Developer. [EAS Build](https://docs.expo.dev/build/setup/)
4. Передайте підписаний артефакт до App Store Connect і перевірте його через TestFlight, зокрема перший запуск без Metro, камеру, галерею, відкриття файла та «Зберегти у Файли». [TestFlight](https://developer.apple.com/testflight/)
5. Підготуйте фактичні скриншоти, контакт підтримки та відомості про конфіденційність для App Store Connect. Перевірте поведінку саме підписаної збірки та її інтегрованих SDK. [Відомості про конфіденційність](https://developer.apple.com/app-store/app-privacy-details/)

## Поведінка даних

Прикладний код зберігає каталог і фото в локальному сховищі. Доступ до камери запитується після натискання кнопки зйомки. Копія JSON не зашифрована і може містити особисті фото й назви місць. Файл передається обраному користувачем системному застосунку через меню поширення. Якщо обрати хмарну папку, її синхронізація регулюється вибраним сервісом.

Експортуйте копію перед видаленням Expo Go, заміною телефона або перенесенням даних у незалежну збірку. Відновлення замінює поточний каталог після підтвердження. Якщо важливі обидва набори даних, збережіть чинний набір окремою копією перед відновленням.

**Стан** — експорт iOS-бандла перевірено в Windows. Підписану збірку, TestFlight та App Store заплановано як окремі етапи.
