# Тест-план

## Виконано у Windows

Середовище — Node.js 22.23.4, npm 10.9.9, Expo SDK 58.

| Перевірка | Фактичний результат |
| --- | --- |
| `npm run typecheck` | TypeScript strict, успішно. |
| `npm run lint` | ESLint, успішно. |
| `npm test` | 10 із 10. Чотири модульні тести домену, два тести формату копії і чотири інтеграційні тести SQLite. |
| `npx expo-doctor` | 20 із 20 перевірок. |
| `npx expo install --check` | Залежності відповідають SDK. |
| `npm run build:ios` | Metro і Hermes експортували iOS-бандл. |
| `npm start` | Metro відповів на перевірку стану і віддав маніфест iOS з runtime `exposdk:58.0.0`. |
| `npm audit` | 0 відомих уразливостей за результатом npm на момент перевірки. |
| `npx expo config --type introspect --json` | У конфігурації iOS версії 1.1.0 наявні українські пояснення доступу до камери та фото. |

Модульні тести охоплюють ввід, український пошук, місце, обране, сортування та перевірку структури копії. Інтеграційні тести виконують SQL застосунку через `node:sqlite` й охоплюють CRUD, зовнішній ключ, міграцію 1 → 2, відкат відновлення, повторне відкриття та демо-записи. Камера, нативний шлях SQLite, файловий обмін, тема, навігація й VoiceOver потребують перевірки на iPhone.

## Ручні сценарії для iPhone

Почніть з Expo Go SDK 58, того самого облікового запису Expo на ПК і телефоні та працюючого Metro. Під час повторного запуску відкрийте той самий проєкт і не очищайте дані Expo Go.

| ID | Дії | Очікуваний результат |
| --- | --- | --- |
| M01 | Відкрийте чистий проєкт. Перейдіть на кожну вкладку. | Огляд показує 0 речей, 4 категорії, 0 місць та порожні останні записи. У каталозі є дія додавання. |
| M02 | Відкрийте форму речі та збережіть її без назви. Повторіть з назвою без категорії. | З’являється повідомлення про відповідне поле. Лічильник не змінюється. |
| M03 | Створіть «Інструменти». Збережіть «Ліхтарик» з цією категорією, місцем, описом та фото. | Річ є в огляді й каталозі. Деталі показують фото, поля і дату. Лічильники оновлено. |
| M04 | Додайте «Ліхтар для кімнати» до іншої категорії. Введіть «ЛІХ» і виберіть «Інструменти». Потім введіть «їжак». | Спочатку два збіги без фільтра, далі один. Для «їжак» — порожній стан з кнопкою скидання. |
| M05 | Змініть місце зберігання і замініть фото. Відкрийте деталі повторно. | Видно нове місце і фото, дата додавання та сама. |
| M06 | Спробуйте видалити зайняту категорію, перейменуйте її, а потім видаліть річ із підтвердженням та видаліть категорію. | Зайнята категорія захищена, нова назва з’являється в речі. Після вилучення речі порожню категорію можна видалити. |
| M07 | Пройдіть M03, закрийте Expo Go і знову відкрийте проєкт. Після завантаження ввімкніть авіарежим і змініть місце речі. | Запис і фото збережені. Пошук і зміна полів працюють після втрати мережі. |
| M08 | Відкрийте вибір фото, скасуйте його, далі збережіть без фото. В іншому записі натисніть «Прибрати фото» і збережіть. | Відміна вибору не змінює попереднє фото. Після видалення копії оригінал доступний у «Фото». |
| M09 | У вкладці «Дані» скасуйте підтвердження демо-даних, потім погодьтесь і повторіть. | Скасування не додає записів. Після згоди з’являється до чотирьох речей із позначкою «Демо», без дублювання збережених прикладів. |
| M10 | Перейдіть у темну тему, збільшіть системний розмір тексту і ввімкніть VoiceOver. | Написи читаються, кнопки та вкладки доступні, вибір категорії оголошується, основні дії можна виконати. |
| M11 | Дозвольте камеру у формі. Зробіть фото, збережіть, відкрийте окремий перегляд. Повторіть зі скасуванням зйомки. | Фото зберігається й доступне після повторного відкриття. Скасування не замінює попереднє фото. |
| M12 | Відмовте в доступі до камери. Виберіть готове фото або збережіть запис без фото. | Форма лишається доступною. Застосунок пояснює, як працювати з іншим джерелом або повернути дозвіл. |
| M13 | Позначте річ зіркою й відкрийте «Обране». Після перезапуску знайдіть її за частиною місця та змініть сортування. | Позначка зберігається. Список відображає вибраний порядок і спільні умови фільтрації. |
| M14 | Експортуйте копію до «Файлів». Створіть контрольний запис, відкрийте копію, підтвердьте заміну. | Контрольний запис зникає. З копії повертаються фото, обране, дати й порожні категорії. |
| M15 | Виберіть пошкоджений файл. Потім виберіть коректний, але скасуйте підтвердження. | Пошкодження пояснюється. В обох випадках поточний каталог зберігається. |
| M16 | Оновіть проєкт зі збереженим каталогом 1.0.0 без очищення сховища. | Категорії, речі, місця й фото зберігаються. Нова позначка обраного доступна зі значенням «вимкнено». |

**Статус M01–M16** — потрібен фізичний iPhone. Після виконання внесіть дату, версію iOS, фактичний результат і номер відповідного знімка в пояснювальну записку.
